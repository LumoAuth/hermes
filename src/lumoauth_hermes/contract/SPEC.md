# LumoAuth Guard for personal agents — contract v1

This document is the contract that every LumoAuth Guard host plugin
(`@lumoauth/openclaw`, `lumoauth-hermes`) and the LumoAuth server implement.
The catalog (`catalog/`) and the test vectors (`vectors/`) are part of it:
a plugin conforms when it passes every vector. When this file and a vector
disagree, the vector wins and this file has a bug.

Keywords MUST, MUST NOT, SHOULD and MAY are used as in RFC 2119.

## 1. Goal and threat model

A personal agent (OpenClaw, Hermes) runs tools for a language model on the
owner's machine: it reads and writes files, runs shell commands, browses the
web, sends messages and calls MCP servers. The model reads text that other
people wrote (web pages, e-mail, chat messages, files), so it must be treated
as **untrusted**: a prompt injection can make it ask for any tool call.

The Guard decides every tool call **outside the model**, in a hook of the host
process, before the tool runs. It protects:

| Area | What the Guard does |
|---|---|
| Tool calls | Every call is classified (§4) and allowed, sent to a person for approval, or blocked (§6). Policy lives in LumoAuth: the agent's capabilities. |
| Its own integrity | Hard rules (§5) that no setting, capability or approval can lift: the agent cannot read the Guard's key, change the host's or the Guard's configuration, disable or update plugins, or run the host's admin commands. |
| Secrets on disk | Credential stores (SSH, cloud, package registries, browser profiles, `.env` files) cannot be read or written without a person's approval, whatever the capabilities say. |
| Exfiltration after untrusted input | After the session took in untrusted content (web pages, e-mail), actions that send data out need approval even when granted (§6.3, "taint"). |
| Identity | The agent authenticates with its own key pair (`private_key_jwt`, RFC 7523) and sender-constrained tokens (DPoP, RFC 9449). The private key never leaves the machine; no shared secret exists. |
| Kill switch | Suspending, deactivating or deleting the agent in LumoAuth stops every tool call within one refresh interval (§7.2). |
| Accountability | Every decision becomes an audit entry in LumoAuth (tool-call receipts, §7.4). |
| Host hardening | `doctor` (§9) checks the host's own security settings (sandboxing, who may message the agent, exposed gateways, file permissions, plaintext secrets) and says what to change. |

**Trusted:** the owner, the LumoAuth server, the host process and its plugin
loader, the operating system user account of the owner.
**Untrusted:** the model's output (tool names, arguments, text), every
content it reads, MCP servers' tool descriptions.

**Limits (MUST be stated in each plugin's README):**
- The Guard runs inside the host process. An agent that can run arbitrary
  code (shell, `execute_code`) as the same OS user could in principle modify
  files the Guard cannot see it touch: shell strings are scanned (§5.3) but
  scanning a shell command is a tripwire, not a sandbox. The strongest setup
  combines the Guard with the host's sandbox (OpenClaw
  `agents.defaults.sandbox.mode`, Hermes `terminal.backend: docker`), which
  `doctor` recommends.
- Calls that the host does not route through its tool hook are not seen
  (Hermes: subprocesses started from inside an `execute_code` script, `!cmd`
  shell escapes, `--safe-mode`; OpenClaw: none known in 2026.11.5).

## 2. Components

Each host plugin ships:

1. **Runtime gate**: a pre-tool-call hook (decision, §6) and a post-tool-call
   hook (receipt completion, §7.4).
2. **Setup** command: `openclaw lumoauth setup` / `hermes lumoauth setup` (§8).
3. **Status** command: identity, mode, capabilities, connectivity, queued
   receipts, recent decisions.
4. **Doctor** command: host hardening checks (§9). OpenClaw also registers
   them as a security-audit collector so `openclaw security audit` shows them.
5. **Lock / unlock** commands: a local panic switch (§6.1 step 1).
6. **Reset** command: deletes the local key and configuration (the agent in
   LumoAuth stays until the owner deletes it; the command prints where).
7. The **skill** `lumoauth-guard` (`skills/lumoauth-guard/SKILL.md`), which
   tells the model what the Guard is and how to behave when a call is
   blocked or waits for approval.

## 3. Files

All Guard state lives in the **Guard home**: `$LUMOAUTH_GUARD_HOME`, else
`~/.lumoauth/guard/<host>/` where `<host>` is `openclaw` or `hermes`
(directory mode `0700`, files `0600`).

| File | Content |
|---|---|
| `config.json` | Settings (§3.1). |
| `agent-key.pem` | The agent's private key: EC P-256, PKCS#8 PEM. Generated by setup. |
| `lock` | Present while the local lock is on. Content: ISO-8601 time and reason. |
| `receipts-queue.jsonl` | Receipts not yet delivered (bounded, §7.4). MAY be kept in memory only. |

The Guard home is protected by §5 (no read, no write by the agent).


| Key | Values | Default | Meaning |
|---|---|---|---|

| `onUngranted` | `ask`, `block` | `ask` | A call whose capability is not granted asks a person, or is blocked. |
| `taint.escalate` | subset of risks (§4.2), plus `egress` | `["external"]` | Risks that need approval after untrusted input. `egress` adds the tools that can carry data out in a URL (`web_fetch`, browser tools) even when their risk is lower. Strict: `["external","execute","egress"]`. |
| `refreshSeconds` | 30–600 | 60 | How often the capability snapshot is refreshed. |
| `offlineGraceSeconds` | 0–3600 | 300 | How long a snapshot may be used when LumoAuth cannot be reached. |

default and be reported by `status`.

## 4. Classifying a tool call

The plugin turns `(toolName, arguments)` into a **classification**:

```json
{ "tool": "write", "capability": "files:write", "risk": "write", "ingestsUntrusted": false,
  "persistsInstructions": false, "egress": false, "paths": ["/home/ada/notes.md"],
  "command": null, "server": null, "mcpTool": null, "hardRule": null }
```

`tool` is the host's tool name after the catalog's aliases (`bash` → `exec`).
`server` / `mcpTool` are the MCP server (sanitised) and the tool's own name
(as the host gave it) for MCP tools. `hardRule` is the catalog's tool rule
(`deny`, `approve` or null, §5.2); path and command rules (§5.1, §5.3) are
evaluated separately. `command` is the first non-empty `commandArgs` value.

### 4.1 Capability names

A capability is the LumoAuth agent capability (an OAuth scope value in the
canonical form `<resource>:<action>`) that allows the call. Matching uses the
server's rule (`vectors/agent-capabilities.json`, the same cases that
LumoAuth's server and SDKs pass): exact match, `*`, or a `prefix:*`
wildcard, after normalisation.

| Tools | Capability |
|---|---|
| Built-in tools | From the host catalog (`catalog/<host>.json`). |
| MCP tools | `mcp:<server>:<risk>:<tool>` (§4.3). |
| Plugin tools and anything not in the catalog | `tool:<name>` with risk `execute`. |

`<server>` and `<tool>` are lower-cased; every character outside
`[a-z0-9_-]` becomes `_`. A host's MCP name is split as follows:

- OpenClaw: `<server>__<tool>` (first `__`). OpenClaw sanitises server names
  to `[A-Za-z0-9_-]`, at most 30 characters.
- Hermes: `mcp__<server>__<tool>`.

A tool name that looks like an MCP name but whose server is not configured on
the host is still classified as MCP (the server list is advisory).

### 4.1a Dispatcher tools

Some hosts expose most tools through one wrapper that the model calls with
the real tool's name (OpenClaw `dispatch_action {id, args}` from its tool
search catalog). A dispatcher is decided **as the call it dispatches**:

1. The wrapper call is classified as the dispatched tool (catalog lookup by
   the `id` / `name` argument, its `args` as the arguments) and decided by §5
   and §6 exactly like a direct call. The decision of the wrapper is that
   decision; the receipt names the dispatched tool.
2. When the decision allows the call (allowed or approved), the Guard keeps
   a **pre-decision** for (session, dispatched tool name, SHA-256 of its
   canonical arguments) for 60 s. When the host then runs the dispatched
   tool through the hook as well, the hook finds the pre-decision, allows it
   without asking again and without a second receipt (the post-tool-call
   hook completes the one receipt). A pre-decision is used once.
3. A wrapper call without a resolvable tool name is classified
   `tool:<wrapper>` with risk `execute` (asks).
4. A dispatched name made of `:`-separated parts (OpenClaw tool-search ids
   such as `openclaw:core:web_fetch`, `<source>:<plugin>:<name>`) is reduced
   to its last part before the catalog lookup and the pre-decision key: the
   host runs and hooks the tool under that plain name.

This is safe whether or not the host also hooks the inner call: the
decision is made on the inner call in both cases, and a person is asked at
most once. Dispatcher tools are listed in the host catalog with
`"dispatcher": {"nameArgs": [...], "argsArg": "..."}`.

### 4.2 Risk levels

| Risk | Meaning | Examples |
|---|---|---|
| `read` | Reads local or account data, no side effects. | `read`, `read_file`, `search_files`, `memory_search` |
| `write` | Changes local data in the workspace or the agent's own memory. | `write`, `edit`, `apply_patch`, `memory` |
| `execute` | Runs code or commands: can do anything the OS user can. | `exec`, `terminal`, `execute_code`, unknown tools |
| `external` | Sends data or acts outside the machine on the owner's behalf. | `message`, `sessions_send`, MCP `send_*`, `post_*` |
| `destructive` | Deletes or irreversibly changes external data. | MCP `delete_*`, `drop_*` |
| `admin` | Changes the host, other agents, schedules, devices or credentials. | `gateway`, `automations`, `nodes`, `browser_vault` |

`ingestsUntrusted: true` marks tools whose **result** carries text from
outside (web pages, search results, e-mail, other people's messages): after
such a call the session is tainted (§6.3).

`egress: true` marks tools that reach an address the model chooses (web
pages, browsers): they can carry data out in a URL even when they only read.
They are escalated under taint only when `taint.escalate` contains `egress`
(off by default: a browsing agent would otherwise ask before every page).

`persistsInstructions: true` marks tools that store text the model will read
in later sessions (memory, personal instructions): while the session is
tainted they need approval whatever `taint.escalate` says (§6.3), so that an
injection cannot plant itself in memory.

### 4.3 MCP tools

The risk of an MCP tool is derived from its name by `catalog/mcp-verbs.json`:
the tool name is split into words at `_`, `-`, `.`, spaces and camelCase
boundaries; the **first** word that appears in a verb list decides the base
risk (for that word, lists are checked in the order `destructive`,
`external`, `admin`, `write`, `read`); no listed word → `execute`. A base
risk of `read` or `write` becomes `admin` when **any** word is in the
`admin` list (`get_secret`, `list_permissions`).
`ingestsUntrusted` is true for a tool whose risk is `read` when the server
name contains a word of `untrustedServerWords` (mail, inbox, slack, discord,
browser, web, fetch, search, …) or the tool name contains a word of
`untrustedToolWords` (words split as above).

The capability carries the risk (`mcp:github:read:list_issues`) so that an
owner can grant `mcp:github:read:*` ("read tools of github") without listing
them. The classification is deterministic and local; a malicious MCP server
can mis-name a tool, which is why its tools still go through the taint and
approval rules.

### 4.4 Arguments that the rules read

The host catalog names, per tool, where paths and commands are:
`pathArgs` (argument names holding a path), `commandArgs` (holding a shell
command or code). OpenClaw's `derivedPaths` (hook event) are added to the
paths. `patchArgs` hold a patch in the `apply_patch` format: every line
starting `*** Add File: `, `*** Update File: `, `*** Delete File: ` or
`*** Move to: ` names a path; a unified diff (`--- a/x`, `+++ b/x`) names
the paths after the `a/` / `b/` prefix (`/dev/null` is ignored). Paths are
listed in order of first appearance, without duplicates.

For MCP tools and tools not in the catalog (which have no `pathArgs`), every
string argument value — at any depth of the arguments, at most 200 values —
that starts with `/` or `~/` (or is exactly `~`) is a path. Their column is
"read" when the tool's risk is `read`, else "write". This stops a filesystem
MCP server from reading `~/.ssh/id_rsa` around the file-tool rules. Relative paths are resolved against the host's workspace directory
(OpenClaw: `agents.defaults.workspace`, default `~/.openclaw/workspace`;
Hermes: the terminal's working directory, default the process cwd). `~`,
`$HOME`, `${HOME}` are expanded; `..` is resolved lexically; symlinks are resolved on the deepest
existing ancestor (`realpath`), so a write below a symlinked folder is caught,
and both forms are checked. A symlinked state dir or Guard home is protected
under its real path too.

## 5. Hard rules (no setting, capability or approval lifts these)

Evaluated before anything else. Two outcomes: **deny** (blocked, decision
`blocked`) and **approve** (a person must approve this call even when the
capability is granted; `rememberApprovals` does not apply).

### 5.1 Paths

| Class | Paths | File tools: read | File tools: write | In a shell command |
|---|---|---|---|---|
| `guard` | Guard home (`~/.lumoauth/` as a whole) | deny | deny | deny |
| `hostConfig` | OpenClaw: `<state>/openclaw.json*`, `<state>/.env`, `<state>/credentials/**`, `<state>/agents/*/agent/**`, `<state>/npm/**`, `<state>/extensions/**`, `<state>/state/**`; `$OPENCLAW_CONFIG_PATH`. Hermes: `<home>/config.yaml`, `<home>/.env`, `<home>/auth.json`, `<home>/mcp-tokens/**`, `<home>/plugins/**`, `<home>/plugin-data/**`, `<home>/shell-hooks-allowlist.json`. Plus the plugin's own install directory. | deny | deny | deny |
| `hostSkills` | OpenClaw `<state>/skills/**`, `<state>/plugin-skills/**`; Hermes `<home>/skills/**` | allowed (normal rules) | deny | approve |
| `hostState` | the rest of the host state dir (OpenClaw `<state>` = `$OPENCLAW_STATE_DIR` or `~/.openclaw`; Hermes `<home>` = `$HERMES_HOME` or `~/.hermes`), **except** the workspace dirs (OpenClaw `<state>/workspace*/**` and the configured workspace) and `allowPaths` | deny | deny | approve |
| `secrets` | `~/.ssh/**`, `~/.gnupg/**`, `~/.aws/**`, `~/.azure/**`, `~/.config/gcloud/**`, `~/.kube/**`, `~/.docker/config.json`, `~/.npmrc`, `~/.pypirc`, `~/.netrc`, `~/.git-credentials`, `~/.config/gh/hosts.yml`, `~/.password-store/**`, `~/Library/Keychains/**`, browser profiles (`~/.config/google-chrome/**`, `~/.config/chromium/**`, `~/.mozilla/**`, `~/Library/Application Support/Google/Chrome/**`, `~/Library/Application Support/Firefox/**`), `extraProtectedPaths` | deny | deny | deny |
| `secretFile` | any file named `.env` or `.env.*` (except `.env.example`, `.env.sample`, `.env.template`, `.env.dist`), `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, `id_ecdsa*` outside the classes above | approve | approve | approve |
| `persistence` | shell start-up files (`~/.bashrc`, `~/.bash_profile`, `~/.profile`, `~/.zshrc`, `~/.zprofile`, `~/.zshenv`, `~/.config/fish/config.fish`), `~/.config/autostart/**`, `~/.config/systemd/user/**`, `~/Library/LaunchAgents/**` | allowed (normal rules) | approve | approve |

The first matching class in the table's order wins. `extraProtectedPaths`
behave like `secrets`. Pattern syntax: `<dir>/**` matches the directory
itself and everything below it; `*` matches within one path segment; a
pattern ending in `*` after a file name matches that prefix
(`openclaw.json*` covers `openclaw.json.bak`). Comparison is
case-sensitive on Linux and case-insensitive on macOS and Windows.

Which column applies: a path from `pathArgs`, `patchArgs` or `derivedPaths`
of a tool whose risk is `read` uses "read", of a `write`-capable file tool
uses "write" (risks `write`, `destructive`); paths of shell and code tools
(any tool with `commandArgs`) use "in a shell command".

### 5.2 Tools

| Tool | Rule |
|---|---|
| OpenClaw `plugins` | deny (manages plugins) |
| OpenClaw `gateway` with action `update.run`, `restart`, `update.cleanup` | approve |
| OpenClaw `openclaw` | approve |
| OpenClaw `secrets` | approve |
| Hermes `manage_connections`, `browser_vault` | approve |
| Tools that write skills (OpenClaw `skill_workshop`; Hermes `skill_manage` with an action other than `list`/`view`) | approve: a skill is instructions for every future session, the most durable place for a prompt injection to hide |

### 5.3 Shell commands and code

For `commandArgs` (shell commands, code), the Guard scans the text after
expanding `~`, `$HOME` and `${HOME}`:

- **Tokens**: the text is split at whitespace and the characters
  `;` `|` `&` `<` `>` `(` `)` `'` `"` `` ` `` and `=`. A token is path-like
  when it contains `/`, starts with `~` or `.`, or matches a `secretFile`
  name. Each path-like token is resolved against the working directory (the
  tool's `workdir`/`cwd` argument when present, else the host's) and
  classified by §5.1 with the "in a shell command" column.
- **Substrings**: independently, the expanded text is searched for the
  absolute form of every `guard`, `hostConfig` and `secrets` root (catches
  `--file=/home/ada/.ssh/x` and paths inside code strings), and for their
  home-relative forms (`.openclaw/openclaw.json`, `.lumoauth/`, `.ssh/`,
  `.hermes/.env`, …) as used after `cd ~`.

The strictest result of tokens, substrings and the patterns below wins
(deny over approve).

**deny** when it:
- references a `guard`, `hostConfig` or `secrets` path (§5.1) as a
  path-like token;
- runs the host's admin CLI: `openclaw` followed by `plugins`, `plugin`,
  `config`, `lumoauth`, `hooks`, `security`, `update`, `doctor --fix`,
  `gateway` + (`stop`, `restart`, `install`, `uninstall`); `hermes`
  followed by `plugins`, `plugin`, `config`, `lumoauth`, `setup`, `update`,
  `hooks`; and either name with `--safe-mode`;
- installs, removes or updates the plugin or host packages: `npm`, `pnpm`,
  `yarn`, `bun` with `install`, `i`, `add`, `uninstall`, `remove`, `rm`,
  `update`, `upgrade`, `link` and an argument `openclaw` or
  `@lumoauth/openclaw`; `pip`, `pip3`, `uv pip`, `pipx` with `install`,
  `uninstall`, `upgrade` and `hermes-agent` or `lumoauth-hermes`;
- stops the host: `pkill`/`killall` naming `openclaw` or `hermes`;
  `systemctl` / `launchctl` with `stop`, `disable`, `unload`, `bootout`
  naming `openclaw` or `hermes`;
- sets `HERMES_SAFE_MODE`, `OPENCLAW_CONFIG_PATH`, `OPENCLAW_STATE_DIR`,
  `OPENCLAW_PROFILE`, `OPENCLAW_HOME`, `LUMOAUTH_GUARD_HOME` or `HERMES_HOME`;
- runs `openclaw doctor --fix` / `--repair`.

**approve** when it:
- references a `hostState`, `secretFile` or `persistence` path;
- reads another process's environment: `/proc/<n>/environ`;
- edits the crontab (`crontab` with `-e`, `-r` or a file argument) or uses
  `at`;
- (only while tainted) pipes into a shell or interpreter (`| sh`, `| bash`,
  `| zsh`, `| python`, `| node`), or decodes and runs (`base64 -d`, `xxd -r`
  together with `sh`, `bash`, `eval`, `exec`).

The scan is a tripwire (see §1, Limits). It MUST NOT be weakened to reduce
noise; noise is reduced by the sandbox recommendations of `doctor`.

## 6. Decision

### 6.1 Order

For every tool call, in this order (first match decides):

1. **Local lock** on → `blocked` ("Locked by the owner: run `<host> lumoauth unlock`").
2. **Not set up** (no `config.json` or no key) → `blocked` ("LumoAuth Guard is not set up: run `<host> lumoauth setup`").
3. **Hard rules** (§5): deny → `blocked`; approve → remembered, continue.
4. **Snapshot** (§7.2): none, older than `refreshSeconds + offlineGraceSeconds`, or the agent is not `active` → `blocked` ("LumoAuth cannot confirm this agent's permissions"). This comes before any approval, so that suspending the agent in LumoAuth stops every call, including calls a person would be asked about.
   - A hard-rule approve from step 3 → step 7 with reason "protected".
5. **Capability granted** (snapshot, or the server in `server` mode):
   - if tainted and (the risk is in `taint.escalate`, or `egress` is in `taint.escalate` and the tool has `egress`, or the tool `persistsInstructions`) → step 7 with reason "after untrusted content";
   - else → `allowed`.
6. **Not granted**: `onUngranted: block` → `denied`; else step 7 with reason "not granted".
7. **Approval** (§6.4): approved → `approved`; refused → `refused`; no answer → `expired`; no channel / `approvals: off` → `denied` (reason given).

After the decision, if the call ran and the tool `ingestsUntrusted`, the
session becomes tainted (§6.3).

The block message given to the model MUST name the reason, and for steps 6/7
how the owner can grant it permanently: "Ask the owner to add the capability
`<cap>` to the agent in LumoAuth: <portal agent URL>". It MUST NOT contain
the capability list, the key, tokens or URLs with secrets.

### 6.2 Decision modes

- `local` (default): step 5 matches the classification's capability against
  the snapshot's capabilities. No Ask API call; works on every LumoAuth plan.
- `server`: step 5 calls `POST /agents/ask` with
  `{"action": "<capability>", "context": {"tool": "<name>", "server": "<server|null>", "host": "<host>"}, "audit": "always"}`.
  An `allowed: true` answer MAY be cached per capability for 30 s. A 403
  `plan_limit_reached` or a network error → step 4 rules (snapshot) apply
  for that call and `status` reports it. The `audit_id` goes in the receipt.

### 6.3 Taint

A session (OpenClaw `sessionKey` or `sessionId`; Hermes `session_id`, else
`task_id`) is **tainted** for `taint.windowSeconds` after a call to a tool
with `ingestsUntrusted` ran (decision `allowed` or `approved`). OpenClaw:
also when a tool call's `requester.senderIsOwner === false` (the session is
acting on a message from someone who is not the owner): the session is
tainted for the whole window from then on, because that text stays in the
model's context. While tainted, step 5
escalates risks in `taint.escalate` to approval. Taint is per session, in
memory, and is cleared on restart.

### 6.4 Approvals

Channels, by `approvals`:

- `lumoauth`: a LumoAuth approval request (§7.5) to `ownerUserId`. LumoAuth
  delivers it to the owner's LumoAuth app and to the organization's Slack and
  Discord approval channels that have agent approvals switched on; the first
  answer counts. Needs `canActOnBehalfOfUsers` (a plan feature). If the
  server answers 202 (`email_fallback_sent`) or 428 (`no_enrolled_device`) or
  403 (`delegation_not_permitted`), no channel reached a person and the call
  is `denied` with that reason.
- `host`: the host's own approval UI:
  - OpenClaw: return `requireApproval` (§10.1). The host shows it in the
    Control UI and on chat channels with approval support, and blocks when no
    one can answer (cron, heartbeat, non-interactive runs).
  - Hermes: return `{"action": "approve", …}` (§10.2). **If Hermes's
    `approvals.mode` is `off` or yolo is on, Hermes grants without asking:
    the Guard MUST return `block` instead** ("approvals are switched off in
    Hermes"). The same applies when the current context is unattended (cron,
    single query) and Hermes's mode for that context approves.
- `auto` (default): `lumoauth` when `canActOnBehalfOfUsers` is true, else
  `host`. When `lumoauth` answers 202/428/403 or cannot be reached, `auto`
  falls back to `host` for this call.
- `off`: no approval; the call is `denied`.

Approval text (both channels) is built **only** from the classification and
the arguments, never from the model's own explanation:

- title (≤ 80 chars): `Allow <tool>?` (MCP: `Allow <tool> on <server>?`)
- in title and description, control characters (other than the line breaks
  that join lines) and bidirectional-override / zero-width characters are
  replaced with `�`, so model-chosen text cannot disguise itself.
- description (≤ 480 chars): one line per fact: `Why: <reason>` (the reason
  text of the decision, exactly as in `vectors/decide.json` `reasons`), `Capability: <cap>`,
  `Risk: <risk>`, then up to 5 argument lines `<name>: <value>` with values
  cut to 80 chars, newlines shown as `⏎`, command arguments first and the
others sorted by name (Unicode code point order), and the value of any argument whose
  name contains `password`, `secret`, `token`, `key`, `auth`, `cookie` or
  `credential` replaced by `[hidden]`. For a command argument the whole
  command is shown (cut to 240 chars).
- impact (LumoAuth push): `read`→`low`, `write`→`medium`,
  `execute`/`external`→`high`, `destructive`/`admin`→`critical`.

`rememberApprovals` applies only to approvals whose reason is
`not_granted`. Approvals for a hard rule (`hard_rule_approve`) or for taint
(`tainted`) are asked every time: a person's earlier "always" for sending
e-mail must not let an injected request send e-mail after the agent read a
web page.

- OpenClaw: `allow-always` is not persisted by the host; the Guard keeps it
  in memory for the session and capability, and offers it only for
  `not_granted` approvals. Otherwise, and with `rememberApprovals: false`, the
  Guard offers only `allow-once` and `deny`.
- Hermes: `rule_key` = `lumoauth:<capability>` (Hermes then honours "session"
  and "always" itself); hard-rule and taint approvals and
  `rememberApprovals: false` use `lumoauth:<capability>:<random>` so that every
  call asks.

## 7. LumoAuth protocol (agent side)

All paths are relative to `baseUrl`; `{org}` = `orgId`.

### 7.1 Token

`POST {tokenEndpoint}` (form): `grant_type=client_credentials`,
`client_id=<agentId>`,
`client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer`,
`client_assertion=<JWT>`, header `DPoP: <proof>`.

- Assertion: header `{"alg":"ES256","typ":"client-authentication+jwt","kid":<keyId>}`,
  claims `iss`=`sub`=`agentId`, `aud`=`issuer` (one string), `iat`, `exp`=`iat`+60,
  `jti` (16 random bytes, base64url).
- DPoP: an **ephemeral** P-256 key per process (in memory only). Proof per
  RFC 9449: header `{"typ":"dpop+jwt","alg":"ES256","jwk":<public>}`, claims
  `jti`, `htm`, `htu` (no query/fragment), `iat`, plus `ath` (base64url
  SHA-256 of the access token) on resource requests. A `use_dpop_nonce`
  error or `DPoP-Nonce` header → retry once with `nonce`.
- Resource requests: `Authorization: DPoP <token>` + `DPoP: <proof>`.
- Refresh the token 60 s before `expires_in`. One request in flight.

### 7.2 Snapshot

`GET /orgs/{org}/api/v1/agents/me` → `{identity: {agent_id, status}, capabilities: [..], scope: [..]}`.
Refreshed every `refreshSeconds` in the background and before a decision when
older than `refreshSeconds`. `capabilities` is the snapshot. A token request
answering `invalid_client` / 401, or `/me` answering 401/403, or `status`
not `active`, clears the snapshot (step 4 then blocks). Network errors keep
the last snapshot for `offlineGraceSeconds`.

### 7.3 Ask (server mode)

`POST /orgs/{org}/api/v1/agents/ask` as in §6.2.

### 7.4 Receipts

`POST /orgs/{org}/api/v1/agents/me/tool-calls` with `{"calls": [..]}` (≤ 50).
One receipt per decision, completed by the post-tool-call hook when the call
ran:

```json
{ "tool": "github__create_issue", "server_id": "github", "decision": "approved",
  "outcome": "succeeded", "duration_ms": 840,
  "arguments_sha256": "<hex of SHA-256 of canonical JSON of the arguments>",
  "audit_id": "<from Ask, server mode>", "occurred_at": "<RFC 3339 UTC>",
  "error_code": "<short code>" }
```

- Canonical JSON: keys sorted at every level, no whitespace, UTF-8,
  `JSON.stringify`-compatible number and string forms.
- `outcome`: `succeeded`, `failed`, `not_run` (blocked/denied/refused/expired).
- A receipt whose call never completes is sent without `outcome` after 10 min.
- Flush every 5 s or at 20 queued; at most 1,000 queued (oldest dropped,
  counted in `status`); 429/5xx/network → keep and retry with back-off; 400
  → drop the batch and log it (a bug).
- `receipts: false` sends none.

### 7.5 LumoAuth approval (phone, Slack, Discord)

`POST /orgs/{org}/api/v1/agents/me/approvals` with:

```json
{ "task_id": "<host>-<toolCallId or random>",
  "reason": "<the §6.4 description, cut to 480>",
  "impact": "<§6.4 impact>",
  "on_behalf_of": "<ownerUserId>",
  "expires_in": 170,
  "meta": { "kind": "tool_call", "host": "openclaw", "tool": "gmail__send_email",
            "server": "gmail", "capability": "mcp:gmail:external:send_email",
            "risk": "external", "why": "After the agent read untrusted content",
            "title": "Allow send_email on gmail?",
            "args": ["to: alex@example.com", "subject: Report"],
            "arguments_sha256": "<hex>" } }
```

- `expires_in` (60–600 s, default 120): how long a person may answer. The
  Guard sends the time that it will keep polling (OpenClaw: hook timeout −
  10 s; Hermes: `hook_callback_timeout` − 5 s), so an answer always reaches a
  waiting call.
- `meta.args` are the argument lines of §6.4 (at most 5, already cut and
  with secret values hidden); `meta.title` and `meta.why` as in §6.4. The
  server treats every `meta` value as untrusted text: it cleans and escapes
  it before showing it in the app, Slack or Discord.

→ 201 `{approval_token, status: "pending", expires_at, delivery: ["push", "slack", "discord"]}`
(`delivery` lists where the request went); poll
`GET /agents/me/approvals/{approval_token}/status` every 2 s until `approved`,
`denied` or `expired` (or `expires_at`). Each approval is used for exactly
one call. While waiting, the Guard tells the host where the person can answer
("Waiting for approval in Slack").

### 7.6 Usage (optional)

`POST /orgs/{org}/api/v1/agents/me/usage` `{"tokens": n}` when the host
exposes model token usage (Hermes `post_api_request` `usage.total_tokens`;
OpenClaw `llm_output` `usage.total`, which needs
`plugins.entries.lumoauth.hooks.allowConversationAccess: true`). Batched per
minute.

## 8. Setup and enrollment

### 8.1 What setup does

1. Find LumoAuth: `--url <dashboard URL>` (e.g.
   `https://app.lumoauth.dev/orgs/acme/portal`) or ask for it. The base URL is
   the origin; the organization is the path segment after `/orgs/`.
   `--region eu` → `https://eu.app.lumoauth.dev`.
2. Inventory: the host's built-in tools (catalog) and MCP servers from the
   host's configuration (OpenClaw `mcp.servers`, Hermes `mcp_servers`). No MCP
   server is started.
3. Ask (or take from flags) the preset (`observer`, `assistant`
   (default), `builder`; `catalog/presets.json`), and approvals (`auto`).
4. Generate the P-256 key, write `agent-key.pem` (`0600`), compute the JWK
   thumbprint (RFC 7638) as `keyId`.
5. Start an enrollment (§8.2) with the preset's capability checklist;
   print the verification URL, the user code and the key fingerprint (the
   first 4 groups of 4 characters of the thumbprint, e.g. `Zx3a-91Kc-…`).
6. Poll until approved, denied or expired.
7. Write `config.json`; configure the host (§10); run a self-test (token,
   snapshot, one receipt with tool `lumoauth.selftest`); print the granted
   capabilities and the `doctor` summary.

Setup MUST NOT need an administrator token on the agent's machine.

### 8.2 Enrollment API (server)

**Start** — `POST /orgs/{org}/api/v1/agents/enrollments` (no credential):

```json
{
  "name": "OpenClaw on mac-mini",
  "host": "openclaw",
  "host_label": "mac-mini.local",
  "jwks": {"keys": [{"kty": "EC", "crv": "P-256", "x": "…", "y": "…", "kid": "…", "use": "sig", "alg": "ES256"}]},
  "capabilities": [
    {"scope": "files:read", "risk": "read", "label": "Read files", "checked": true},
    {"scope": "shell:exec", "risk": "execute", "label": "Run shell commands", "checked": false}
  ],
  "delegation": true,
  "inventory": {"tools": 41, "mcp_servers": [{"name": "github"}]}
}
```

- `name` ≤ 100, `host` ∈ `openclaw`, `hermes`, `other`, `host_label` ≤ 100;
  text is cleaned like other untrusted text.
- `jwks`: public keys only (private members refused), one or two keys.
- `capabilities`: 1–200 entries; `scope` a canonical capability
  (`<resource>:<action>`, scope-token syntax, dot form refused); `risk` one of
  §4.2; `label` ≤ 120; `checked` bool.
- `delegation`: the agent asks to act on behalf of the approving person
  (needed for LumoAuth push approvals).
- `inventory`: display only (≤ 100 servers, names ≤ 64).

→ `201`:

```json
{ "enrollment_code": "<43 chars, secret>", "user_code": "BCDF-GHJK",
  "verification_uri": "https://…/orgs/acme/portal/agents/enroll",
  "verification_uri_complete": "https://…/orgs/acme/portal/agents/enroll?code=BCDF-GHJK",
  "key_fingerprint": "Zx3a-91Kc-p0Qe-7tLm",
  "expires_in": 900, "interval": 5 }
```

Errors: `400 invalid_request` (`error_description` names the field),
`404` unknown organization, `429` rate limited.

**Poll** — `POST /orgs/{org}/api/v1/agents/enrollments/token` with
`{"enrollment_code": "…"}`:

- `400 {"error": "authorization_pending"}` while waiting;
- `400 {"error": "slow_down"}` when polled faster than `interval`;
- `400 {"error": "access_denied"}` when the person refused;
- `400 {"error": "expired_token"}` after expiry or after the result was delivered once;
- `200`:

```json
{ "agent_id": "agt_…", "client_id": "agt_…",
  "issuer": "https://app.lumoauth.dev/orgs/acme/api/v1",
  "token_endpoint": "https://app.lumoauth.dev/orgs/acme/api/v1/oauth/token",
  "key_id": "<kid of the registered key>",
  "capabilities": ["files:read", "web:search"],
  "can_act_on_behalf_of_users": true,
  "owner_user_id": "<UUID of the approving person>",
  "agent_url": "https://app.lumoauth.dev/orgs/acme/portal/agents/<id>" }
```

The result is delivered **once** (an approval made in the last seconds can
still be fetched for 120 s after `expires_in`). The enrollment code is not a
credential of the agent: whoever holds it learns the agent's id, never a way
to act as it.

Server details that clients rely on:
- An enrolled agent is created with DPoP-only tokens: a token request
  without a `DPoP` proof is refused, and its tokens are not accepted as
  plain bearer tokens.
- A key sent without `kid` is stored with its RFC 7638 thumbprint as `kid`;
  `key_id` in the result is the `kid` to put in the assertion header.
- `label` and `checked` are optional (defaults: the scope, `false`);
  `host_label` is optional; unknown fields are ignored; a repeated `scope`
  or a scope that is not already canonical is refused.
- `access_denied` also covers an agent deleted between approval and poll.
- A user token or API key sent to these routes is refused (403): send no
  credential.

**Approval page** — `/orgs/{org}/portal/agents/enroll?code=…`: a signed-in
person with `agents.create` reviews the name, host, host label, key
fingerprint ("matches the one in your terminal?"), the capability checklist
(grouped by risk, pre-ticked as `checked`, editable) and delegation, and
approves or denies. The approver becomes the agent's creator and owner; the
usual rules apply (capability containment, plan limits, the delegation plan
feature). The page warns: approve only if you ran the setup command yourself
just now and the code and fingerprint match.

## 9. Doctor

Each check has an id, a level (`ok`, `info`, `warn`, `critical`), a one-line
finding and a fix. Required checks:

| Id | Both hosts |
|---|---|
| `guard.setup` | set up, key present, `config.json` and key mode `0600`, Guard home `0700` |
| `guard.connectivity` | token + snapshot work; agent status |
| `guard.approvals` | approvals channel usable (host approvals reachable / LumoAuth delegation on) |
| `guard.hook-timeout` | the host's hook timeout is ≥ 150 s when `approvals` may use `lumoauth` |
| `secrets.plaintext` | API keys in plaintext files (host `.env`, config) — count only, never print values |
| `fs.permissions` | host config and credential files not readable by group/others |

| Id | OpenClaw |
|---|---|
| `openclaw.sandbox` | `agents.defaults.sandbox.mode` is `off` → warn (recommend `non-main` or `all`) |
| `openclaw.exec` | `tools.exec.mode`/`security` is `full` without sandbox → warn |
| `openclaw.elevated` | `tools.elevated.enabled` with a wildcard `allowFrom` → critical |
| `openclaw.dm-policy` | any `channels.*.dmPolicy: open` → critical |
| `openclaw.gateway-bind` | gateway bound beyond loopback without auth → critical |
| `openclaw.config-readonly` | `OPENCLAW_CONFIG_READONLY` not set → info |
| `openclaw.plugins-allowlist` | `plugins.allow` empty → info |

| Id | Hermes |
|---|---|
| `hermes.approvals-mode` | `approvals.mode: off` or yolo → critical (Guard approvals would be skipped) |
| `hermes.terminal-backend` | `terminal.backend: local` → warn (recommend `docker`) |
| `hermes.allowed-users` | a gateway platform with `*_ALLOW_ALL_USERS` / `GATEWAY_ALLOW_ALL_USERS` → critical; no allow-list (Hermes falls back to pairing) → info |
| `hermes.approvers` | `approvals.approvers` is `["*"]` on a group platform → warn |
| `hermes.hook-timeout` | `plugins.hook_callback_timeout` < 150 when LumoAuth approvals are on → warn |
| `hermes.safe-mode` | note that `--safe-mode` disables every plugin, including the Guard → info |

`doctor --json` prints the checks as JSON. Doctor never changes anything.

## 10. Host bindings

### 10.1 OpenClaw (`@lumoauth/openclaw`, plugin id `lumoauth`)

- `api.on("before_tool_call", handler, { priority: -1000 })`: the **lowest**
  priority, so the Guard judges the parameters that the tool will really get
  (handlers that run earlier can rewrite `params`; a block from any handler is
  terminal).
- Results: allow → `undefined`; block → `{ block: true, blockReason }`;
  approval → `{ requireApproval: { title, description, severity, timeoutMs: 120000, allowedDecisions, onResolution } }`
  (`severity`: `info` for read/write, `warning` for execute/external,
  `critical` for destructive/admin and hard-rule approvals).
- `after_tool_call` (fire-and-forget): completes the receipt (`error` →
  `failed`, else `succeeded`; `durationMs`).
- Setup sets `plugins.entries.lumoauth.enabled: true` and, when LumoAuth
  approvals may be used, `plugins.entries.lumoauth.hooks.timeouts.before_tool_call: 180000`
  through the host's config writer.
- CLI: `api.registerCli` with `openclaw lumoauth setup|status|doctor|lock|unlock|reset`.
- Chat command `/lumoauth` (owner only): status and lock.
- `registerSecurityAuditCollector`: the doctor checks.
- Skill: manifest `skills: ["skills"]`.

### 10.2 Hermes (`lumoauth-hermes`, plugin name `lumoauth`)

- `ctx.register_hook("pre_tool_call", cb)`: returns `None` (allow),
  `{"action": "block", "message": …}` or
  `{"action": "approve", "message": <description>, "rule_key": …}`.
- `ctx.register_hook("post_tool_call", cb)`: completes the receipt
  (`status`: `ok` → `succeeded`; `error`, `timeout` → `failed`; `blocked`,
  `cancelled` → `not_run`); `post_approval_response` records the person's
  answer for the receipt (`once`, `session`, `always` → `approved`; `deny` →
  `refused`; `timeout`, `cancelled`, `notify_failed` → `expired`).
- Hook callbacks MUST return within Hermes's `plugins.hook_callback_timeout`
  (default 30 s): network work happens on a background thread, and LumoAuth
  push polling is capped at `hook_callback_timeout - 5` s.
- Setup adds `lumoauth` to `plugins.enabled` and, when LumoAuth approvals may
  be used, sets `plugins.hook_callback_timeout: 180`.
- CLI: `ctx.register_cli_command("lumoauth", …)` → `hermes lumoauth setup|status|doctor|lock|unlock|reset`.
- Slash command `/lumoauth` (status, lock).
- Skill: `ctx.register_skill("lumoauth-guard", path)`.
- Packaging: a directory plugin (`plugin.yaml`, `manifest_version: 2`,
  `api_version: 1`) and a pip entry point `hermes_agent.plugins: lumoauth`.
