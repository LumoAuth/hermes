# LumoAuth Guard for Hermes Agent v0.1.3 (`v0.1.3`)

**Release Date:** November 24, 2026  
**Tag:** `v0.1.3` (signed), commit `265ff2ea05e7108653b3d6138d1db558e94acadb`

## Package

| Package | Registry | Version |
| :--- | :--- | :--- |
| `lumoauth-hermes` | PyPI | `0.1.3` |
| `lumoauth/hermes` | GitHub, for `hermes plugins install` | tag `v0.1.3` |

The Hermes plugin name is `lumoauth`. Like 0.1.2, this release follows version 1 of the [LumoAuth Guard contract](https://github.com/lumoauth/agent-guard).

The Hermes maintainers reviewed the plugin a second time for Hermes's plugin catalog. This release makes the change that they asked for: reporting is opt-in. The Guard sends receipts and token counts to LumoAuth only when you say yes in setup. The Guard classifies and decides tool calls as before.

---

## Install

```sh
hermes plugins install lumoauth/hermes --enable --yes-deps
hermes lumoauth setup
```

Hermes scans every plugin before it installs it. The scan reports that this plugin names credential paths such as `~/.ssh`, and asks you to confirm. The Guard names those paths to protect them, so answer `y`. In a script, add `--force` to the install command.

Setup asks for your LumoAuth dashboard address, a preset and where a person should approve calls. It then asks whether to send receipts and token counts to LumoAuth. Both answers default to no. Then it prints a link, a code and a key fingerprint. Open the link, check that the code and the fingerprint match your terminal, and approve the agent. Then restart Hermes, or the Hermes gateway.

**Other ways to install:**

- **With pip**, in the Python environment that runs Hermes: `pip install lumoauth-hermes==0.1.3`, then `lumoauth-hermes setup`. Setup turns the plugin on in Hermes's `config.yaml`.
- **Pinned to this release:** `hermes plugins install lumoauth/hermes` follows the `main` branch. To stay on 0.1.3, pass the tag's commit: `hermes plugins install lumoauth/hermes --ref 265ff2ea05e7108653b3d6138d1db558e94acadb --enable --yes-deps`. Hermes then refuses `update` for the plugin.

**Upgrade from 0.1.2, 0.1.1 or 0.1.0:** after a git install, run `hermes plugins update lumoauth`. After a pip install, run `pip install -U lumoauth-hermes==0.1.3`. Your key and settings in `~/.lumoauth/guard/hermes/` stay as they are, so you don't need to run setup again. Read [After an upgrade](#3-after-an-upgrade) first: token counts stop unless you turn them on.

**Requirements:**

- Hermes Agent 0.21.6 or later, on Python 3.11 or later.
- A LumoAuth organization. The Guard works on every LumoAuth plan. Approvals in the LumoAuth app, Slack and Discord need the Agent Governance add-on.

The package depends only on `cryptography` and `httpx`, which Hermes Agent already installs.

## What Changed

### 1. Receipts and Token Counts Are Opt-In

Hermes's catalog rules say that a plugin reports to an outside service only when the user agrees. In 0.1.2, the Guard sent both of these by default:

- **Receipts.** One entry in LumoAuth's audit log for each decision. A receipt holds the tool, the decision, how the call ended and a SHA-256 digest of the arguments, never their values.
- **Token counts.** The number of model tokens that the agent used, once a minute. LumoAuth counts them against the token budgets that you set for the agent.

Now both settings default to `false`:

| Setting in `config.json` | 0.1.2 default | 0.1.3 default |
| :--- | :--- | :--- |
| `receipts` | `true` | `false` |
| `reportUsage` | `true` | `false` |

**Approval requests don't change.** When a call needs a LumoAuth approval, the request still carries the tool, the reason, the capability, the risk and up to five argument lines. The person needs these to decide. Secret values stay hidden, as before. Approvals aren't reporting, so these settings don't affect them.

### 2. Setup Asks About Each One

`hermes lumoauth setup` asks two yes/no questions. Press Enter to answer no.

```text
LumoAuth can keep an audit log of the Guard's decisions. Each entry names the tool, the decision and how the call ended, with a SHA-256 hash of the arguments. The arguments stay on this machine.
Send a receipt for each decision to LumoAuth? [y/N]:

LumoAuth can count the model tokens that the agent uses, for the token budgets that you set for it.
Send the number of tokens to LumoAuth once a minute? [y/N]:
```

Setup writes your answers into `config.json`. In 0.1.2, it always wrote `"receipts": true`.

- **In a script:** `--receipts` and `--report-usage` answer yes. `--no-receipts` and `--no-report-usage` answer no. With `--yes` and neither flag, setup answers no to both.
- **After approval,** setup prints what you chose: `Receipts: off. Token counts: off.`
- **The self-test** sends its test receipt only when receipts are on. Otherwise it prints `Self-test: receipt .......... skipped (receipts are off)`.
- **`status`** has a new `Reporting:` row, for example `receipts off, token counts off`. `status --json` has a new `reportUsage` field next to `receiptsEnabled`.
- **The README** has a new section, "What it sends to LumoAuth". It lists each request that the Guard makes, and when.

To change a setting later, edit `receipts` or `reportUsage` in `~/.lumoauth/guard/hermes/config.json`. The Guard reads the file again when it changes.

### 3. After an Upgrade

An upgrade keeps your `config.json` as it is, so the result depends on what setup wrote there:

| | After the upgrade | Why |
| :--- | :--- | :--- |
| Receipts | Stay **on** | Setup in 0.1.0 to 0.1.2 wrote `"receipts": true`. |
| Token counts | **Stop** | Setup never wrote `reportUsage`, so the new default `false` applies. |

- **To keep token counts,** for example when you set token budgets for the agent, add `"reportUsage": true` to `config.json`.
- **To stop receipts,** set `"receipts": false`.

### 4. Contract Note

The contract now states the opt-in rule. SPEC §3.1 lists `receipts` and `reportUsage`, both `false` by default, and says that an approval request isn't reporting. §7.4 and §7.6 send receipts and usage only when their key is `true`. §8.1 adds the two setup questions and their flags, and runs the self-test receipt only when receipts are on. The contract stays at version 1.

## Known Limitations

The [limitations of 0.1.2](./v0.1.2.md#known-limitations) still apply. They include that the plugin isn't in Hermes's plugin catalog yet. This release answers the second catalog review, and the catalog entry isn't merged yet. Two more details:

- **Receipts stay on after an upgrade.** The Guard can't tell a `"receipts": true` that you chose from one that an older setup wrote. Check the `Reporting:` row of `hermes lumoauth status`.
- **Token budgets need token counts.** When `reportUsage` is off, LumoAuth gets no token counts from the agent. A token budget for the agent then never runs out.
