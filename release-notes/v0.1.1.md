# LumoAuth Guard for Hermes Agent v0.1.1 (`v0.1.1`)

**Release Date:** November 20, 2026  
**Tag:** `v0.1.1` (signed), commit `f3a90f40ed616d4015fdd16b081b55f93ba7f82e`

## Package

| Package | Registry | Version |
| :--- | :--- | :--- |
| `lumoauth-hermes` | PyPI | `0.1.1` |
| `lumoauth/hermes` | GitHub, for `hermes plugins install` | tag `v0.1.1` |

The Hermes plugin name is `lumoauth`. Like 0.1.0, this release follows version 1 of the [LumoAuth Guard contract](https://github.com/lumoauth/agent-guard).

This release names the oldest Hermes Agent release that the plugin supports, 0.21.6. It also adds tests inside a real Hermes Agent at every release and every week. The Guard's code is the same as in 0.1.0, and it checks tool calls exactly as before.

---

## Install

```sh
hermes plugins install lumoauth/hermes --enable --yes-deps
hermes lumoauth setup
```

Hermes scans every plugin before it installs it. The scan reports that this plugin names credential paths such as `~/.ssh`, and asks you to confirm. The Guard names those paths to protect them, so answer `y`. In a script, add `--force` to the install command.

Setup asks for your LumoAuth dashboard address, a preset and where a person should approve calls. Then it prints a link, a code and a key fingerprint. Open the link, check that the code and the fingerprint match your terminal, and approve the agent. Then restart Hermes, or the Hermes gateway.

**Other ways to install:**

- **With pip**, in the Python environment that runs Hermes: `pip install lumoauth-hermes==0.1.1`, then `lumoauth-hermes setup`. Setup turns the plugin on in Hermes's `config.yaml`.
- **Pinned to this release:** `hermes plugins install lumoauth/hermes` follows the `main` branch. To stay on 0.1.1, pass the tag's commit: `hermes plugins install lumoauth/hermes --ref f3a90f40ed616d4015fdd16b081b55f93ba7f82e --enable --yes-deps`. Hermes then refuses `update` for the plugin.

**Upgrade from 0.1.0:** after a git install, run `hermes plugins update lumoauth`. After a pip install, run `pip install -U lumoauth-hermes==0.1.1`. Your key and settings in `~/.lumoauth/guard/hermes/` stay as they are, so you don't need to run setup again.

**Requirements:**

- Hermes Agent 0.21.6 or later, on Python 3.11 or later.
- A LumoAuth organization. The Guard works on every LumoAuth plan. Approvals in the LumoAuth app, Slack and Discord need the Agent Governance add-on.

The package depends only on `cryptography` and `httpx`, which Hermes Agent already installs.

## What Changed

### 1. The Oldest Supported Hermes Agent: 0.21.6

`plugin.yaml` now declares `requires_hermes: ">=0.21.6"`. On an older Hermes Agent, Hermes skips the plugin instead of loading it. Version 0.21.6 is the oldest numbered Hermes Agent release that the plugin is tested with.

### 2. Tests Inside a Real Hermes Agent

`tests/test_real_hermes.py` loads the plugin into Hermes Agent itself. It checks that the hooks, the commands and the skill load, and then checks these cases:

- Reading a secret is blocked.
- A granted tool runs, and its audit entry is sent.
- An ungranted tool asks a person, through Hermes's own approval prompt.
- When the person approves once, the tool runs. When the person refuses, it doesn't.
- With no person present, the call is blocked.
- With Hermes's `approvals.mode` set to `off`, the Guard blocks the call instead of letting Hermes approve it.
- `hermes lumoauth` runs.

In 0.1.0, the release run skipped these tests, because they need Hermes Agent. Now:

- **Every release** installs Hermes Agent `main` from its own lockfile, and runs the whole test suite inside it. No test may skip. Then it runs `hermes plugins validate --install-deps`, the check that Hermes's plugin catalog uses.
- **Every week**, CI runs the same tests inside Hermes Agent `main` and 0.21.6, and runs `hermes plugins validate` on `main`.

### 3. The `reportUsage` Setting Is Documented

The Guard reports the number of model tokens that the agent uses to your LumoAuth organization, once a minute. LumoAuth counts them against the token budgets that you set for the agent. The README now lists this setting. To turn the reports off, set `reportUsage` to `false` in the Guard's `config.json`. The reports are on by default, as in 0.1.0.

## Known Limitations

The [limitations of 0.1.0](./v0.1.0.md#known-limitations) still apply, including that the plugin is not in Hermes's plugin catalog yet. Two more details:

- **A Hermes Agent without a version number loads the plugin.** A Hermes Agent that runs from a git checkout may not know its own version. Hermes then can't compare it with `requires_hermes`, and loads the plugin anyway.
- **`hermes plugins validate` gives two warnings.** The security scan reports `caution`, because the plugin names credential paths such as `~/.ssh` in order to block them. The plugin also imports two private Hermes modules, `tools.approval` and `tools.approval_context`. The Guard uses them to learn when Hermes would approve a call without asking a person (`--yolo`, `approvals.mode: off`, unattended `approve` modes), so that it can block that call instead. When these modules are missing or change, the Guard falls back to Hermes's `config.yaml` and `HERMES_YOLO_MODE`.

## Compatibility and Verification

- 353 tests pass on Python 3.14 outside Hermes Agent. The real-Hermes test module skips there, because Hermes Agent isn't installed.
- Inside Hermes Agent `main` (commit `242315c`, on the release day), all 363 tests pass, and none skip. `hermes plugins validate --install-deps` passes, with the two warnings above.
- Before the release, the same tests passed inside Hermes Agent 0.21.6, 0.22.0, 0.22.7, 0.23.0 and 0.23.3.
- CI runs the tests on Python 3.11 to 3.14 on Linux, and on macOS.
- The wheel holds the `lumoauth_hermes` package, its copy of the contract and the `lumoauth-guard` skill, and registers the entry point `hermes_agent.plugins: lumoauth = lumoauth_hermes:register`. The sdist is also a Hermes directory plugin. Its `plugin.yaml` says `version: 0.1.1`, and it has a root `__init__.py`.
- After the upload, the release run installed `lumoauth-hermes==0.1.1` from PyPI into a new virtual environment on Python 3.14. It checked the version, the entry point, the contract copy and the skill. It also checked that `lumoauth-hermes` runs and prints `0.1.1`.
- The files on PyPI have no provenance attestation.
