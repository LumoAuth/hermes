# LumoAuth Guard for Hermes Agent v0.1.0 (`v0.1.0`)

**Release Date:** November 20, 2026  
**Tag:** `v0.1.0` (signed), commit `171703fefb0401c515a6b514412be77eecf71b37`

## Package

| Package | Registry | Version |
| :--- | :--- | :--- |
| `lumoauth-hermes` | PyPI | `0.1.0` |
| `lumoauth/hermes` | GitHub, for `hermes plugins install` | tag `v0.1.0` |

The Hermes plugin name is `lumoauth`. This release follows version 1 of the [LumoAuth Guard contract](https://github.com/lumoauth/agent-guard), as of `agent-guard` commit `54f19ba`.

This is the first release. LumoAuth Guard checks every tool call that your Hermes agent makes, before the tool runs. Each call is allowed, sent to a person for approval, or blocked. You keep the rules in LumoAuth, not in the conversation, so a prompt injection cannot change them. The check runs in Hermes's own process, outside the model.

---

## Install

```sh
hermes plugins install lumoauth/hermes --enable --yes-deps
hermes lumoauth setup
```

Hermes scans every plugin before it installs it. The scan reports that this plugin names credential paths such as `~/.ssh`, and asks you to confirm. The Guard names those paths to protect them, so answer `y`. In a script, add `--force` to the install command.

Setup asks for your LumoAuth dashboard address, a preset and where a person should approve calls. Then it prints a link, a code and a key fingerprint. Open the link, check that the code and the fingerprint match your terminal, and approve the agent. Then restart Hermes, or the Hermes gateway.

**Other ways to install:**

- **With pip**, in the Python environment that runs Hermes: `pip install lumoauth-hermes==0.1.0`, then `lumoauth-hermes setup`. Setup turns the plugin on in Hermes's `config.yaml`.
- **Pinned to this release:** `hermes plugins install lumoauth/hermes` follows the `main` branch, and `hermes plugins update lumoauth` pulls it again. To stay on 0.1.0, pass the tag's commit: `hermes plugins install lumoauth/hermes --ref 171703fefb0401c515a6b514412be77eecf71b37 --enable --yes-deps`. Hermes then refuses `update` for the plugin.

**Requirements:**

- Hermes Agent, on Python 3.11 or later.
- A LumoAuth organization. The Guard works on every LumoAuth plan. Approvals in the LumoAuth app, Slack and Discord need the Agent Governance add-on.

The package depends only on `cryptography` and `httpx`, which Hermes Agent already installs.

## Highlights

### 1. Every Tool Call Is Checked Before It Runs

The Guard checks each call in Hermes's `pre_tool_call` hook. That covers:

- Built-in tools, MCP tools (`mcp__<server>__<tool>`) and the tools of other plugins.
- The tools of `delegate_task` sub-agents.
- The tool calls that `execute_code` scripts make.

Every tool call is blocked until setup finishes. The Guard fails closed on purpose.

The first step that applies gives the answer:

1. **Locked:** blocked until you run `hermes lumoauth unlock`.
2. **Not set up:** blocked.
3. **Protected:** blocked, or sent for approval (see [Hard Rules](#2-hard-rules-that-no-setting-removes)).
4. **No confirmation from LumoAuth:** blocked when the agent is suspended, or when LumoAuth cannot confirm the agent's permissions for longer than 5 minutes.
5. **Granted:** the call runs. After untrusted content, a call that sends data out asks a person first.
6. **Not granted:** asks a person. Set `onUngranted` to `block` to block it instead.

Each tool call maps to one capability:

| Kind of tool | Capability | Example |
| :--- | :--- | :--- |
| Built-in tools | A fixed capability for each tool | `files:read`, `shell:exec`, `messages:send` |
| MCP tools | `mcp:<server>:<risk>:<tool>` | `mcp:github:read:list_issues`. Grant `mcp:github:read:*` to allow every read tool of the GitHub server. |
| Plugin tools | `tool:<name>` | `tool:weather` |

The risk of an MCP tool comes from the tool's name. Hermes writes a server called `my-server` as `my_server` in tool names, so grant `mcp:my_server:...`. A Hermes tool that is not in the plugin's catalog counts as `tool:<name>` with the risk `execute`, and asks a person until you grant it.

When a call is blocked, the model receives the reason. When a capability is missing, the message names it and links to the agent's page in LumoAuth.

### 2. Hard Rules That No Setting Removes

No setting, capability or approval lets the agent:

- Read the Guard's key or change the Guard's files.
- Change Hermes's settings, turn plugins off or update Hermes.
- Run `hermes plugins`, `hermes config` or `hermes lumoauth`.
- Start Hermes in safe mode, which loads no plugins.
- Read or write `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, browser profiles, or Hermes's `.env`, `auth.json` and `mcp-tokens`.

A `.env` or `*.pem` file outside those places needs a person's approval every time.

For MCP and plugin tools, argument values that start with `/` or `~/` are checked as paths, for example for a filesystem MCP server. The agent may read Hermes's skills, but writing them as files is blocked.

### 3. Scans of Shell Commands and Code

Before `terminal` or `execute_code` runs, the Guard scans the command or code for protected paths, including paths relative to the home directory, and for protected commands. A scan finds known patterns only. It is not a sandbox: see [Known Limitations](#known-limitations).

### 4. Extra Care After Untrusted Content

After the agent reads a web page, search results, an e-mail or chat messages, the session counts as holding untrusted content for 30 minutes.

- During that time, a call that sends data out needs approval, even when its capability is granted.
- Writing to memory or to skills needs approval too.

### 5. No Silent Approvals

Hermes approves calls without asking in some modes: when `approvals.mode` is `off`, under `--yolo` or `/yolo`, and in a cron job whose `approvals.cron_mode` is `approve`. In those modes the Guard blocks the call instead, so that no call skips the person.

### 6. Approvals Where You Are

The `approvals` setting chooses where a person answers:

| Setting | Where you approve |
| :--- | :--- |
| `auto` (default) | Through LumoAuth when the agent may act for its owner. Otherwise, or when LumoAuth cannot reach anyone, in Hermes's own prompt. |
| `lumoauth` | Only through LumoAuth. |
| `host` | Only in Hermes's own prompt: the panel in the terminal, or the `/approve` and `/deny` buttons in a chat. |
| `off` | Nowhere: every call that needs approval is blocked. |

**Through LumoAuth:** each request goes to the owner only. LumoAuth sends it to the owner's LumoAuth app and to the organization's Slack and Discord approval channels, and the first answer counts. The call stays on hold until a person answers. `hermes lumoauth status` and `/lumoauth` show where to answer, for example "Waiting for approval in Slack". These approvals need the agent's **Can act on behalf of users** switch in LumoAuth.

Hermes stops waiting for a plugin after `plugins.hook_callback_timeout` seconds, 30 by default. Setup sets it to 180 when LumoAuth approvals are possible.

**In Hermes:** the prompt offers "once", "session" and "always". This works on every LumoAuth plan.

- The Guard honours "session" and "always" only for a capability that the agent was not granted.
- For protected files and commands, and after untrusted content, every call asks again.

Every request shows the tool, the reason, the capability, the risk and up to five arguments. The values of arguments with names such as password, token, key or cookie are hidden. Characters that could disguise text are shown as `�` (U+FFFD).

### 7. Agent Identity and Enrollment

- Setup creates an EC P-256 key pair on your machine. The private key never leaves it.
- The agent signs in to LumoAuth with `private_key_jwt`. Its tokens work only with a short-lived key that the Hermes process holds (DPoP). There is no shared secret.
- You approve the agent on a LumoAuth page that shows the same code and key fingerprint as your terminal. Setup never needs an admin token.
- The Guard keeps its files in `~/.lumoauth/guard/hermes/` (mode `0700`, files `0600`). Set `LUMOAUTH_GUARD_HOME` to use another directory.

### 8. Capabilities From LumoAuth

- **`local` mode (default):** the Guard loads the agent's capabilities from LumoAuth every 60 seconds and decides on your machine. This mode works on every plan.
- **`server` mode:** the Guard asks LumoAuth's Ask API about each call, and LumoAuth records each answer.
- When LumoAuth cannot be reached, the last capabilities stay valid for 5 minutes. Then every call is blocked.
- Before every approval, the Guard checks the capabilities again, so a suspended agent cannot ask.
- To stop the agent, suspend or delete it in LumoAuth. Every tool call stops within one minute. On the machine, `hermes lumoauth lock` stops them at once.

### 9. A Record of Every Decision

- Each decision becomes an entry in LumoAuth's audit log, with a SHA-256 digest of the arguments. The argument values never leave your machine.
- Entries that cannot be sent before Hermes stops are kept on disk and sent the next time Hermes starts.
- The Guard also reports the number of model tokens that the agent uses to LumoAuth.

### 10. Presets

Setup asks for a preset. The preset ticks capabilities on the approval page in LumoAuth, and you can change the ticks before you approve.

| Preset | Runs without asking |
| :--- | :--- |
| `observer` | Reading files, searching and opening web pages, reading sessions and media, the read tools of MCP servers. |
| `assistant` (default) | Everything in `observer`, plus writing files and memory, to-do lists, generating media and the write tools of MCP servers. |
| `builder` | Everything in `assistant`, plus shell commands, code, background processes, sub-agents and the browser. |

No preset grants sending messages, scheduled jobs, device control, stored secrets, Hermes administration or skill changes. You grant those on purpose.

### 11. Commands, Doctor and the Skill

| Command | What it does |
| :--- | :--- |
| `hermes lumoauth setup` | Enrolls the agent. `--yes` asks nothing, `--force` replaces an existing setup, `--no-hermes-config` leaves Hermes's `config.yaml` unchanged. |
| `hermes lumoauth status` | Shows the agent, its capabilities, the connection to LumoAuth and the latest decisions. |
| `hermes lumoauth doctor` | Checks the Guard and Hermes's own security settings, and says what to change. It changes nothing. |
| `hermes lumoauth lock` | Stops every tool call on this machine, at once. |
| `hermes lumoauth unlock` | Lets tool calls run again. |
| `hermes lumoauth reset` | Deletes the key and the settings on this machine. |

In a chat, `/lumoauth` shows a short status and `/lumoauth lock` locks the Guard. Unlocking works only in a terminal. The `lumoauth-hermes` command runs the same commands when the plugin is not loaded, for example `lumoauth-hermes doctor`.

The plugin includes the `lumoauth-guard` skill. The skill tells the model what the Guard is, and what to do after a call is blocked or while a person decides on it.

## Known Limitations

- **The Guard is not a sandbox.** It runs inside Hermes. An agent that can run any code as your user (`terminal`, `execute_code`) could change files without the Guard seeing it. Use the Guard with Hermes's Docker backend (`hermes config set terminal.backend docker`), which `doctor` checks.
- **Some calls bypass Hermes's tool hook.** These are subprocesses that an `execute_code` script starts itself, `!cmd` shell escapes typed in the terminal, and tools that another plugin runs directly with `ctx.dispatch_tool`.
- **Safe mode turns the Guard off.** `hermes --safe-mode` and `HERMES_SAFE_MODE=1` start Hermes without any plugin. The Guard stops the agent from starting Hermes that way, but a person can.
- **Other plugins are trusted code.** They run in the same process. A plugin that rewrites a call's arguments (a `modify` answer to `pre_tool_call`) changes them after the Guard has checked them.
- **Plugins in a separate process.** With `plugins.isolation: host`, the Guard may not see a `/yolo` that someone turned on in a chat. Use `approvals: lumoauth` or `off` with that setting.
- **Hermes's program files.** The Guard protects the Hermes home (`~/.hermes`). When Hermes is installed somewhere else, protect that place with file permissions or a container.
- **The plugin is not in Hermes's plugin catalog yet.** A git install follows `main` unless you pin a commit (see [Install](#install)).
